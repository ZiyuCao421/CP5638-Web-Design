## 🌟 About This Repository

This repository is my personal space for collecting everything related to **CP5638 Web Design** — practicals, planning artefacts, website code, usability testing evidence, and research presentation materials.

It serves as:

- 🎯 A **clear, navigable record** of work from Week 1 through to the final assessment
- 📈 A demonstration of **progressive development** from basic HTML to a JavaScript-enabled, responsive website
- 🗂️ An organised **evidence base** for each rubric criterion
- 💡 A **sandbox** for creative experiments and areas of personal interest

> 📬 **This is a development portfolio, not the official submission channel.** Official assessment submissions go through LearnJCU.

### 🌐 Assessment 2 – Basic Website

<details>
<summary><b>🔎 View Assessment 2 details</b></summary>

- **Weight:** 30%
- **Due:** Week 6 (30/10/2026, 11:59 pm)
- **Type:** Individual

Plan and develop a small website using HTML and CSS. Refine/extend the project plan, clearly articulate website goals, and clearly identify the target audience.

**Rubric criteria (each worth 10%):**

- Goals · Success Evaluation · Target Audience · Flowchart · Content
- Navigation · Images · HTML & CSS · Interface Design · Information Design

**Recommended folder structure (an organisational aid, not a mandated filename list):**

```text
assessment2/
├── README.md
├── planning/
│   ├── plan.html
│   ├── wireframe/
│   └── flowchart/
└── website/
    ├── index.html
    ├── ...
    ├── css/
    └── images/
```

The `...` denotes further HTML pages added as the site grows. Specific filenames are not officially mandated — this structure maps evidence to rubric criteria.

</details>

### 🚀 Assessment 3 – Full Website + Research Presentation

<details>
<summary><b>🔎 View Assessment 3 details</b></summary>

- **Weight:** 50% total
  - Full Website: **30%**
  - Oral Research Presentation: **20%**
- **Due:** Week 10 (27/11/2026, 11:59 pm)
- **Type:** Individual
- **SLOs:** SLO1 – SLO4

#### 🌐 Full Website

The website must **build upon and improve** the Basic Website from Assessment 2.

**Official requirements include:**

- Update / improve the basic website
- Make the website **responsive**
- Perform **usability testing**
- Add **form functionality**
- Implement **JavaScript form validation**
- **Publish** the website to a public web server
- **Document changes** to the website and project plan in response to Assessment 2 feedback

**Rubric areas include:**

- Response to feedback and plan updates
- Usability Testing Plan and Results
- Published Website
- Content · Interface Design · Information Design · Information Architecture
- HTML / CSS · JavaScript · Responsiveness

#### 🎤 Research Presentation

**Topic areas:** Accessibility · Usability · Cultural aspects

**Assessment areas:** Background · Motivation · Synthesis · Findings · Conclusion · Delivery style · Selection and use of journal/conference papers

A `README.md` inside each `weekX/` folder acts as a **development record** rather than a one-line note. This is **recommended** (not officially required) to help document progression.

```text

## Practical Overview
## Tasks Completed
## Skills Practised
## Testing
## Problems Encountered
## Solutions
## Tutor Feedback
## Reflection
```

This pattern makes the repository easier to review over time and helps trace development from Week 1 to the final assessments.
